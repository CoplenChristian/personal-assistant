It isderived from the frozen architecture, roadmap, security/privacy documents, thePO acceptance handoff, the architect handoff, and the user's explicit stackdecision.## 1. GoalDeliver a functional local settings lifecycle:~~~textrepository YAML defaults + bootstrap environment        ->typed C# settings registry        ->SQLite global user overrides        ->effective settings snapshot        ->ASP.NET Core localhost API        ->React Settings route~~~The slice is local, single-user, and providerless. It must work withoutAnthropic/OpenAI credentials, Keychain entries, tmux sessions, native CLIs,personal documents, or live external integrations.## 2. Scope and non-goals### In scope- C#/.NET typed settings registry and runtime validation;- loading safe repository defaults from policies/defaults/runtime.yaml;- resolving bootstrap settings before SQLite opens;- SQLite global override persistence with future scope columns;- effective-value and reset semantics;- ASP.NET Core GET/PATCH/DELETE Settings API;- read-only safety and bootstrap projections;- honest not-configured integration cards;- React/Vite /settings route with metadata-driven controls;- deterministic local privacy check;- backend, API, React, Playwright, accessibility, and privacy proof.### Explicitly deferredDo not implement native Claude/Codex lifecycle, tmux management, terminalstreaming, AgentRegistry, dynamic agents, scheduler execution, agent messaging,email/Gmail, EventKit, BlueBubbles, browser providers, Keychain flows, documentindexing, memory search/materialization, multi-user identity, public OAuth,RBAC, tenants, or any direct model API.Do not add per-turn authorization, cryptographic grants, provenance tokens, oran IAM system around native local agents. The broker guardrails in this sliceare configuration/data contracts for later integration boundaries, not asecond security principal system.The UI may display future integration states, but it must not probe credentials,show fake accounts, or claim a provider is connected.## 3. Configuration layers and boot order### 5.1 BootstrapBefore constructing SQLite or resolving any storage-backed setting, resolve andvalidate:| Setting | Environment | Default | UI || --- | --- | --- | --- || system.runtimeDirectory | PA_RUNTIME_DIR | ./runtime | read-only || system.serverHost | PA_SERVER_HOST | 127.0.0.1 | read-only || system.serverPort | PA_SERVER_PORT | 4317 | read-only || system.tmuxPrefix | PA_TMUX_PREFIX | pa- | read-only |The runtime directory is the location of the database and runtime artifacts; itcannot be a database override. The default bind is loopback. Wildcard bindssuch as 0.0.0.0 and :: are rejected by the safe-bind policy unless a laterexplicit deployment decision changes that rule. Tailscale/non-loopback accessis launch-time configuration, not a Settings value.The tmux prefix remains effectively fixed once sessions exist. A future prefixconflict is rejected rather than adopted in a way that orphans sessions. Phase0A may use a fake session detector; real tmux reconciliation is deferred.PA_VAULT_DIR is not a bootstrap database location. It supplies the initialdocuments.vaultPath default and may be overridden as an ordinary userpreference. The settings service does not read, create, watch, or index thevault in this slice.Boot order:1. Resolve and validate bootstrap environment.2. Locate the repository root and load versioned YAML defaults/policies.3. Build the typed registry and baseline effective values.4. Open personal-assistant.sqlite under the resolved runtime directory.5. Load valid global override rows and validate the candidate snapshot.6. Compose the API snapshot.7. Start ASP.NET Core on the validated host/port.If bootstrap, YAML, policy, or persisted override data is malformed, fail closedwith a useful local error. Never silently use an unsafe fallback.### 5.2 Repository defaultsReuse policies/defaults/runtime.yaml. Defaults areread-only source inputs and are never written back by the Settings API. Valuesmarked code-default in the registry catalog below are safe assumptions thatmust be frozen in implementation tests rather than made user-specific.### 5.3 Effective precedenceHard safety invariants constrain every result. Writable settings resolve:~~~textbootstrap-only key -> validated environment/bootstrap valueeditable key       -> global SQLite override, if present                     -> environment/system-derived default, if applicable                     -> repository runtime.yaml default                     -> explicit safe code defaultsafety projection  -> capability/realm/security policy, never an override~~~Only overrides are stored. A reset deletes the row and allows the currentrepository/environment/system default to take effect. No user preference writesto Git-tracked YAML, manifests, templates, or native sessions.## 6. ValidationValidation runs on each scalar and then on the full candidate effectivesnapshot before persistence.- Integers are JSON numbers with no fractional component.- Booleans are actual JSON booleans.- Strings and enums use exact declared values.- Enum values outside the registry options are rejected.- Warning/rotate sizes and histories are positive and bounded.- nativeSessionRotateBytes is strictly greater than  nativeSessionWarningBytes.- Timezone values resolve through .NET TimeZoneInfo.- documents.vaultPath expands a leading home marker, normalizes an absolute  path, rejects empty/NUL/newline values, and rejects a path lexically under  the repository root. It does not inspect the path in 0A.- The server port environment value is validated before the server starts.- Unknown keys, unsupported scopes, bootstrap keys, safety keys, immutable  keys, sensitive definitions, malformed values, and invalid combinations fail  closed.A multi-change PATCH is all-or-nothing. No override row or success event iswritten when any change fails validation.## 8. Persistence and activityUse an explicit migration owned by the harness library:~~~sqlCREATE TABLE settings_overrides (    scope_type TEXT NOT NULL        CHECK (scope_type IN ('global', 'realm', 'agent', 'integration')),    scope_id TEXT NOT NULL DEFAULT '',    key TEXT NOT NULL,    value_json TEXT NOT NULL,    updated_at TEXT NOT NULL,    PRIMARY KEY (scope_type, scope_id, key),    CHECK (        (scope_type = 'global' AND scope_id = '')        OR        (scope_type <> 'global' AND length(scope_id) > 0)    ));~~~Phase 0A accepts only global with scope_id equal to the empty string. Defaultsare never inserted into this table. value_json is canonical JSON for theregistry scalar type; arbitrary objects, policy blobs, credentials, tokens,credential references, and secret-like values are rejected.The minimal activity boundary is:~~~sqlCREATE TABLE activity_events (    id TEXT PRIMARY KEY,    timestamp TEXT NOT NULL,    agent_id TEXT,    realm TEXT,    category TEXT NOT NULL,    operation TEXT NOT NULL,    target TEXT,    status TEXT NOT NULL,    duration_ms INTEGER,    metadata_json TEXT NOT NULL);~~~A committed changed override or reset emits settings.updated throughIActivityEventSink in the same transaction boundary. Metadata containsoperation, global scope, changed keys, and restart-required information. Itnever contains setting values, vault paths, runtime paths, credentials, ortokens. Rejected and no-op requests do not emit a success event.If a persisted override is malformed, do not apply it silently. Return a localsettings-store error and provide a safe recovery path that removes the knownrow; if recovery is not available, return an unavailable/fail-closed error.## 9. HTTP APIAll endpoints are ASP.NET Core localhost routes. There is no public login,multi-user session, or per-turn security protocol in this slice.~~~textGET    /api/settingsPATCH  /api/settingsDELETE /api/settings/{key}~~~### 9.1 GET responseReturn a versioned JSON envelope:~~~json{  "contractVersion": "phase-0a-settings.v1",  "settings": [    {      "key": "appearance.theme",      "category": "General",      "label": "Theme",      "description": "Color scheme used by the local dashboard.",      "valueType": "enum",      "options": ["system", "light", "dark"],      "value": "system",      "defaultValue": "system",      "hasOverride": false,      "source": "repo-default",      "scope": { "type": "global", "id": null },      "editable": true,      "resettable": true,      "requiresRestart": false,      "bootstrap": false,      "sensitive": false,      "constraints": { "options": ["system", "light", "dark"] }    }  ],  "safety": [    {      "key": "safety.emailSending",      "label": "Email sending",      "state": "Disabled",      "source": "capability-policy",      "locked": true,      "reason": "No mail-send capability exists."    }  ],  "integrations": [    { "id": "email", "label": "Email", "status": "not-configured", "phase": "Phase 4" },    { "id": "calendar", "label": "Calendar & Reminders", "status": "not-configured", "phase": "Phase 3" },    { "id": "bluebubbles", "label": "BlueBubbles", "status": "not-configured", "phase": "Phase 5" },    { "id": "browser", "label": "Browser", "status": "not-configured", "phase": "Phase 7" }  ]}~~~Every setting entry includes metadata needed to render the control. Parse the request envelope.2. Require global scope only; Phase 0A does not accept a scope override.3. Resolve exact registry keys.4. Reject unknown, immutable, bootstrap, safety, sensitive, malformed, and   invalid values.5. Merge changes with current effective values.6. Validate the complete candidate snapshot.7. Upsert/delete only the changed global override rows in one transaction.8. Append settings.updated for a changed operation in the same transaction.9. Return the complete effective GET response.If a submitted value equals its current baseline default, canonicalize it as nooverride by deleting any existing row. A valid unchanged request is idempotentand emits no success event.### 9.3 DELETE resetDELETE /api/settings/{key} removes that key's global override and returns thecomplete effective response. Reset is idempotent when no row exists. It rejectsunknown, safety, bootstrap, immutable, and sensitive keys.Use RFC 7807 ProblemDetails with stable error codes:~~~textinvalid_requestunknown_settingunsupported_scopeimmutable_settingbootstrap_settingsensitive_settinginvalid_valuecross_setting_invalidsettings_store_invalidsettings_unavailable~~~A client error identifies the key and reason without echoing sensitive values,full private paths, or credential material.## 10. Privacy checkImplement scripts/privacy-check.sh and run it before staging/public pushes.It must be deterministic, local, providerless, and independent of theapplication database.It checks tracked/staged paths and visible untracked paths, rejecting:- runtime databases, logs, transcripts, caches, browser profiles, screenshots,  downloads, generated state, and personal-document directories;- populated MEMORY.md, HANDOFF.md, or USER.md outside ignored runtime paths;- credential/state artifacts including p12, pfx, token, JSONL, cookies,  storage-state, credentials, secrets, oauth, and tokens paths;- .NET outputs such as bin, obj, TestResults, and generated coverage; and- private-key markers or obvious credential-shaped content.It reports every exact path and reason, uses no network or LLM, and exitsnonzero on any violation. It must pass on a clean source-only checkout.The check is a repository hygiene command, not an ASP.NET endpoint or Settingsmutation hook.## 12.
